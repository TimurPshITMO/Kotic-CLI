# 😼 Kotic CLI: Ваш Пушистый Помощник в Мире Кода

Добро пожаловать в Kotic CLI – умного и проворного AI-агента, разработанного в рамках трека "МегаШкола 2026: Coding Agents"! Kotic – это не просто ещё один инструмент, это ваш надёжный спутник в автоматизации полного цикла разработки программного обеспечения (SDLC) прямо в GitHub.

Цель проекта — имитировать работу настоящего разработчика и ревьюера, но с очаровательной эффективностью и скоростью котика, который знает, что делает!

## ✨ Основные Задачи Kotic CLI

Kotic CLI создан, чтобы сделать процесс разработки более плавным и автоматизированным. Он берёт на себя рутину, позволяя вам сосредоточиться на самом главном:

*   **Автоматизация SDLC в GitHub:** От создания Issue до готового Pull Request – Kotic полностью управляет процессом.
*   **Имитация Разработчика и Ревьюера:** Наш агент не только пишет код, но и критически оценивает его, обеспечивая качество и соответствие задачам.
*   **Непрерывный Цикл Обратной Связи:** Благодаря встроенному AI Reviewer Agent, Kotic способен итерировать и исправлять ошибки, пока задача не будет выполнена идеально.

## 🐾 Kotic's Tech Stack Highlights: Сила и Гибкость

Под капотом у Kotic работает мощный и современный стек технологий, позволяющий ему быть таким умным и быстрым:

*   **Agno - Сердце Наших Агентов:** Мы используем `agno` как основной фреймворк для создания мультимодальных AI-агентов.
    *   **Гибкость LLM:** Благодаря `agno.models.openai.like.OpenAILike`, Kotic может легко интегрироваться с любой моделью, предоставляющей `OpenAI`-совместимый API (например, YandexGPT, GPT-4o-mini). Это позволяет быстро переключаться между провайдерами и использовать лучшие инструменты для каждой задачи, не привязываясь к конкретному поставщику.
    
*   **Безопасные Git-Инструменты:** Пользовательские инструменты для работы с Git, разработанные специально для Kotic, ограничивают возможности агента. Это гарантирует, что он не сможет случайно выполнить `push` на основную ветку (`main`/`master`), вместо создания Pull Request, предотвращая нежелательные изменения и обеспечивая стабильность проекта.
    
*   **Глубокая Интеграция с Git/GitHub:** Kotic напрямую взаимодействует с вашими репозиториями, читает Issues, создаёт Pull Requests и управляет изменениями кода.
*   **FastAPI & Uvicorn - API-Интерфейс для Гибкости:** Kotic использует `FastAPI`, обеспечивая быстрый и надёжный HTTP-интерфейс для обработки вебхуков GitHub и потенциальной интеграции с внешними системами.
*   **uv и Docker - Удобство и Надежность Запуска:** Использование `uv` для сверхбыстрой установки зависимостей и Docker для контейнеризации обеспечивает легкий и воспроизводимый запуск Kotic в любой среде.

## 🚀 Kotic's Workflow in Action: Как Это Работает

Представьте, что у вас есть задача. Kotic берёт её на себя:

1.  **Постановка Задачи:** Вы создаёте Issue в GitHub с описанием задачи.
2.  **Kotic Code Agent Вступает в Игру:** Наш Code Agent получает Issue, анализирует требования, вносит необходимые изменения в код репозитория, фиксирует их и создаёт Pull Request.
3.  **CI/CD и AI Reviewer Agent:** После создания или обновления PR автоматически запускается CI/CD пайплайн. Внутри него активируется наш AI Reviewer Agent, который:
    *   Анализирует изменения кода.
    *   Проверяет результаты CI-тестов.
    *   Сравнивает реализацию с исходными требованиями Issue.
4.  **Обратная Связь:** Результаты анализа публикуются в Pull Request в виде автоматических комментариев, summary и детального code review.

## 🛠 Установка и Запуск

Чтобы запустить Kotic CLI и увидеть его в действии, выполните следующие шаги:

### 1. Установка uv (если ещё не установлен)

```bash
pip install uv
```

### 2. Клонирование репозитория

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd repository/kotic_cli
```

### 3. Установка Зависимостей

Kotic использует `uv` для управления зависимостями. Находясь в директории `repository/kotic_cli`:

```bash
uv sync
```

### 4. Настройка Переменных Окружения

Создайте файл `.env` в директории `repository/kotic_cli` (там же, где `pyproject.toml`) и добавьте необходимые API-ключи и конфигурации.

**Пример `.env`:**
```ini
# Для GitHub App:
# GITHUB_APP_ID: ID вашего GitHub App.
# GITHUB_PRIVATE_KEY_PATH: Абсолютный путь к PEM файлу приватного ключа GitHub App.
# GITHUB_WEBHOOK_SECRET: Секрет, используемый для проверки подписи вебхуков.
GITHUB_APP_ID="<ВАШ_GITHUB_APP_ID>"
GITHUB_PRIVATE_KEY_PATH="<АБСОЛЮТНЫЙ_ПУТЬ_К_ВАШЕМУ_PRIVATE_KEY.pem>"
GITHUB_WEBHOOK_SECRET="<ВАШ_GITHUB_WEBHOOK_SECRET>"

# Для YandexGPT (или другого OpenAI-подобного LLM через agno.models.openai.like.OpenAILike):
# YANDEX_API_KEY: Ваш API-ключ Yandex Cloud.
# YANDEX_API_BASE_URL: Базовый URL для YandexGPT API.
# YANDEX_FOLDER_ID: ID каталога Yandex Cloud.
YANDEX_API_KEY="<ВАШ_YANDEX_API_KEY>"
YANDEX_API_BASE_URL="<ВАШ_YANDEX_API_BASE_URL>" # Например, https://llm.api.cloud.yandex.net/foundationModels/v1/completion
YANDEX_FOLDER_ID="<ВАШ_YANDEX_FOLDER_ID>"
```

### 5. Запуск с Docker

**a. Сборка Docker образа:**
Перейдите в корневую директорию проекта (`D:\Projects\МегаШкола 2026`) и выполните:
```bash
docker build -t kotic_cli -f repository/kotic_cli/Dockerfile .
```
*   `-t kotic_cli`: Присваивает имя `kotic_cli` созданному образу.
*   `-f repository/kotic_cli/Dockerfile`: Указывает путь к Dockerfile.
*   `.`: Указывает контекст сборки (текущая директория), чтобы Docker мог получить доступ к файлам проекта.

**b. Запуск Docker контейнера:**
```bash
docker run -p 8000:8000 ^
    --env-file repository/kotic_cli/.env ^
    -v "<АБСОЛЮТНЫЙ_ПУТЬ_К_ВАШЕМУ_PRIVATE_KEY.pem>:/app/<ИМЯ_ВАШЕГО_PRIVATE_KEY_ФАЙЛА>.pem" ^
    -e GITHUB_PRIVATE_KEY_PATH="/app/<ИМЯ_ВАШЕГО_PRIVATE_KEY_ФАЙЛА>.pem" ^
    kotic_cli
```
*   `-p 8000:8000`: Пробрасывает порт 8000 контейнера на порт 8000 вашей хост-машины, где будет работать FastAPI.
*   `--env-file repository/kotic_cli/.env`: Подгружает переменные окружения из вашего `.env` файла внутрь контейнера.
*   `-v "<АБСОЛЮТНЫЙ_ПУТЬ_К_ВАШЕМУ_PRIVATE_KEY.pem>:/app/<ИМЯ_ВАШЕГО_PRIVATE_KEY_ФАЙЛА>.pem"`: Монтирует файл приватного ключа GitHub App с вашей хост-машины в контейнер по указанному пути.
*   `-e GITHUB_PRIVATE_KEY_PATH="/app/<ИМЯ_ВАШЕГО_PRIVATE_KEY_ФАЙЛА>.pem"`: Устанавливает переменную окружения внутри контейнера, указывающую на путь к файлу приватного ключа ВНУТРИ контейнера.
*   `kotic_cli`: Имя Docker образа для запуска.

### 6. Локальный Запуск

**a. Активация виртуального окружения (если используете):**
Перейдите в директорию `repository/kotic_cli`.
```bash
.venv/Scripts/activate # Для Windows
source .venv/bin/activate # Для Linux/macOS
```

**b. Запуск FastAPI приложения:**
```bash
uvicorn src.kotic_cli.app:app --host 0.0.0.0 --port 8000 --reload
```
*   `--host 0.0.0.0`: Делает приложение доступным по сети (не только с localhost).
*   `--port 8000`: Указывает порт, на котором будет работать приложение.
*   `--reload`: Перезагружает сервер при изменении кода (удобно для разработки).
